# v0.11.0 苏格拉底训练轮次策略设计

## 背景

用户在苏格拉底训练中反馈：两轮对话后很难自然进入第三轮。当前系统的消息存储和聊天输入没有硬编码两轮限制，但训练 prompt 没有明确“至少完成几轮”的约束，页面也没有给用户可配置的轮次入口。

## 目标

- 默认最少完成 3 轮学生回答。
- 最大轮次默认不限制。
- 用户在开始训练前可以设置最少追问轮次和最大追问轮次。
- 未达到最少轮次前，不允许保存复盘。
- 不改数据库结构，不迁移、不覆盖旧数据。

## 非目标

- 不重新设计聊天组件。
- 不强制终止达到最大轮次后的对话。
- 不修改历史会话的 prompt_snapshot。

## 设计

### Prompt 策略

`services.prompts.build_training_prompt()` 增加轮次参数：

- `min_dialogue_rounds`，默认 3，最小值强制为 3。
- `max_dialogue_rounds`，默认 `None`，表示不限制。

生成的 prompt 中加入“对话轮次规则”，要求模型在未达到最少轮次前不得输出最终总结，并且每次回复都要继续提出新的具体追问。

### 页面策略

训练页新增：

- 最少追问轮次输入框。
- 最大追问轮次选择框，默认“不限制”。
- 训练上下文条显示当前轮次规则。
- 训练记录侧栏显示已完成轮次。

### 保存复盘策略

一轮对话定义为：学生完成一次回答。因此系统按 `role == "user"` 的消息数量计算已完成轮次。保存复盘时，如果未满最少轮次，页面拒绝保存并提示继续训练。

## 数据安全

本次更新不修改数据库 schema，不写迁移，不触碰 `data/fashuo.db`、`data/uploads/` 或 `data/documents/`。历史会话保持原样，新会话会在 prompt 快照中保存轮次规则。
